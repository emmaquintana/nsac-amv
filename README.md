# NSAC AMV

## English

### Local development

Requirements: Node.js, Python 3.10 or later, and the backend dependencies.

```bash
cd frontend && npm install
cd ../backend && python -m pip install -r requirements.txt
cd .. && npm run dev
```

The root command checks and downloads the FIRMS data, converts the CSV files to
Parquet, prepares the map index, and calculates daily totals before starting
FastAPI at `http://127.0.0.1:8000` and Vite at `http://localhost:5173`.
**The frontend only starts once all four datasets and all their caches are
ready**; if downloading or preparation fails, the command exits with an error
and does not start the servers. The console shows progress by stage, file, and
percentage. Once the API has finished starting, Vite starts and displays the
frontend URL with the available port, without clearing previous messages.
`WARNING` messages appear in yellow when preparation runs in a terminal.
Initial preparation can take several minutes; caches are saved to disk and
reused as long as the data does not change. Vite forwards `/api` requests to the
backend. To stop both processes, press `Ctrl+C`. To use a different Python
interpreter, set `PYTHON=/path/to/python npm run dev`.

The API documents its routes at `http://127.0.0.1:8000/docs`. The frontend queries
observations and continents directly; the map and time series update when
filters are applied.

### Frontend language

The interface is available in English and Spanish. On startup, it uses the first
supported language from the system/browser preferences; if none is supported,
it uses English. The **EN / ES** button in the header changes the language
without losing filters and saves the choice for future visits in that browser.
Text, dates, and numbers adapt to the selected language.

### Script output language

Project scripts use the system language for console messages, warnings, errors,
command-line help, and displayed summaries. English and Spanish are supported;
other languages fall back to English. Locale environment variables (`LC_ALL`,
`LC_MESSAGES`, `LANGUAGE`, and `LANG`) are respected. Set `NSAC_LANGUAGE=en` or
`NSAC_LANGUAGE=es` to override detection. `npm run dev` passes the detected
language to its child processes. This setting is independent of the frontend's
language selector. Command names and CSV file names and columns stay the same.

### Automatic FIRMS data downloads

The CSV files in `backend/app/data/` are downloaded directly from NASA FIRMS and
ignored by Git. There is no need to install Git LFS or run `git lfs pull`.
Complete local datasets are reused on each startup without network access.
Starting the API directly with Uvicorn also checks the data and prepares the
caches before accepting requests, avoiding that work on the first website visit.

The four configured requests are:

- [MODIS C6.1 — 848778](https://firms.modaps.eosdis.nasa.gov/data/download/DL_FIRE_M-C61_848778.zip)
- [VIIRS NOAA-21 — 848780](https://firms.modaps.eosdis.nasa.gov/data/download/DL_FIRE_J2V-C2_848780.zip)
- [VIIRS S-NPP — 848781](https://firms.modaps.eosdis.nasa.gov/data/download/DL_FIRE_SV-C2_848781.zip)
- [VIIRS NOAA-20 — 848779](https://firms.modaps.eosdis.nasa.gov/data/download/DL_FIRE_J1V-C2_848779.zip)

**Warning:** these files were generated by the FIRMS server on **2026-11-14**.
The links expire **45 days later, on 2026-12-29**. The **latest historical record
date is 2025-11-16**. This warning appears in the logs at the start and end of
preparation (including failures) and when the server shuts down. ZIP downloads
were chosen because the API restricts the date range per query too much and
would have required an excessive number of requests.

The structure and headers described in the
[official FIRMS README](https://firms.modaps.eosdis.nasa.gov/download/Readme.txt)
are preserved. Each of these four requests contains `fire_archive_...` and
`fire_nrt_...` CSV files, plus `Readme.txt`, inside a `DL_FIRE_...` folder. Both
CSV files are checked; a header-only file is valid, but a Git LFS pointer is not.
ZIP files are downloaded and extracted into a temporary directory and installed
only after their contents have been validated; temporary files are then removed.
The first download requires a connection and space for about 4.7 GB of CSV data,
plus the ZIP and temporary extraction of the request being processed.

After the links expire, complete local data continues to work. If files are
missing, request new **CSV** packages from FIRMS and update the requests in
`backend/app/downloads.py`, or restore the original request files locally.
See the [backend documentation](backend/README.md#english) to use other data
paths and prepare query caches.

### Deleting local data

With the servers stopped, run from the project root:

```bash
npm run data:clean -- --dry-run  # Preview which files would be deleted
npm run data:clean             # Delete the files
```

The standalone `scripts/clean-data.mjs` script deletes **CSV and ZIP** files
from `backend/app/data/` and its subfolders, including CSV analysis results.
It preserves Python code, `Readme.txt` files, and folders, and does not follow
symbolic links or junctions. It can also be run with
`node scripts/clean-data.mjs`. It always operates on the project's
`backend/app/data/`; it does not use external paths configured through
environment variables.

Running `npm run dev` again downloads all four FIRMS datasets again. If the
links have expired, update the requests first.

## Español

### Desarrollo local

Requisitos: Node.js, Python 3.10 o posterior y las dependencias del backend.

```bash
cd frontend && npm install
cd ../backend && python -m pip install -r requirements.txt
cd .. && npm run dev
```

El comando raíz comprueba y descarga los datos FIRMS, convierte los CSV a Parquet,
prepara el índice del mapa y calcula los totales diarios antes de iniciar FastAPI
en `http://127.0.0.1:8000` y Vite en `http://localhost:5173`. **El frontend sólo se
inicia cuando los cuatro conjuntos y todas sus cachés están listos**; si una
descarga o preparación falla, el comando termina con error y no inicia los
servidores. La consola muestra el avance de cada etapa por archivo y porcentaje.
Cuando la API termina de arrancar, se inicia Vite y muestra el enlace al frontend
con el puerto disponible, sin borrar los mensajes anteriores. Los avisos
`WARNING` aparecen en amarillo al ejecutar la preparación en una terminal.
Esta preparación puede tardar varios minutos en el primer arranque; las cachés
se guardan en disco y se reutilizan mientras los datos no cambien. Vite reenvía las
solicitudes `/api` al backend. Para
detener ambos procesos, pulsa `Ctrl+C`. Si se usa otro intérprete de Python,
se puede indicar con `PYTHON=/ruta/a/python npm run dev`.

La API documenta sus rutas en `http://127.0.0.1:8000/docs`. El frontend
consulta observaciones y continentes directamente; el mapa y la serie temporal
se actualizan al aplicar filtros.

### Idioma del frontend

La interfaz está disponible en inglés y español. Al iniciar utiliza el primer
idioma compatible de las preferencias del sistema/navegador; si ninguno es
compatible, utiliza inglés. El botón **EN / ES** del encabezado cambia el idioma
sin perder los filtros y guarda la elección para las próximas visitas en ese
navegador. Los textos, las fechas y los números se adaptan al idioma seleccionado.

### Idioma de salida de los scripts

Los scripts del proyecto usan el idioma del sistema para los mensajes de
consola, advertencias, errores, ayuda de comandos y resúmenes mostrados. Se
admiten inglés y español; para otros idiomas se usa inglés. Se respetan las
variables de idioma (`LC_ALL`, `LC_MESSAGES`, `LANGUAGE` y `LANG`). Para elegir
un idioma explícitamente, configura `NSAC_LANGUAGE=en` o `NSAC_LANGUAGE=es`.
`npm run dev` transmite el idioma detectado a los procesos que inicia. Esta
configuración es independiente del selector de idioma del frontend. Se
conservan los nombres de comandos, archivos CSV y columnas.

### Descarga automática de datos FIRMS

Los CSV de `backend/app/data/` se descargan directamente de NASA FIRMS y quedan
ignorados por Git. No hace falta instalar Git LFS ni ejecutar `git lfs pull`.
Los datos locales completos se reutilizan en cada arranque sin acceder a la red.
El arranque directo de la API con Uvicorn también comprueba los datos y prepara
las cachés antes de aceptar peticiones, para evitar ese trabajo en la primera
visita a la web.

Los cuatro pedidos configurados son:

- [MODIS C6.1 — 848778](https://firms.modaps.eosdis.nasa.gov/data/download/DL_FIRE_M-C61_848778.zip)
- [VIIRS NOAA-21 — 848780](https://firms.modaps.eosdis.nasa.gov/data/download/DL_FIRE_J2V-C2_848780.zip)
- [VIIRS S-NPP — 848781](https://firms.modaps.eosdis.nasa.gov/data/download/DL_FIRE_SV-C2_848781.zip)
- [VIIRS NOAA-20 — 848779](https://firms.modaps.eosdis.nasa.gov/data/download/DL_FIRE_J1V-C2_848779.zip)

**Advertencia:** estos archivos fueron generados por el servidor de FIRMS el
**2026-11-14**. Los enlaces expiran **45 días después, el 2026-12-29**. La **fecha
máxima histórica de los registros es 2025-11-16**. Esta advertencia aparece en los
logs al inicio y al final de la preparación (también si falla), y al apagar el
servidor. Se eligieron descargas ZIP porque la API limita demasiado el rango de
días por consulta y habría exigido una cantidad excesiva de solicitudes.

Se conserva la estructura y los encabezados descritos en el
[README oficial de FIRMS](https://firms.modaps.eosdis.nasa.gov/download/Readme.txt).
Cada uno de estos cuatro pedidos contiene CSV `fire_archive_...` y
`fire_nrt_...`, más `Readme.txt`, en una carpeta `DL_FIRE_...`. Ambos CSV se
comprueban; un archivo con sólo encabezado es válido, pero un puntero de Git LFS
no lo es. Los ZIP se descargan y extraen en un directorio temporal y sólo se
instalan después de validar su contenido; se eliminan los temporales al terminar.
La primera descarga requiere conexión y espacio para unos 4,7 GB de CSV, además
del ZIP y la extracción temporal del pedido en curso.

Después del vencimiento, los datos locales completos siguen funcionando. Si
faltan archivos, solicita nuevos paquetes **CSV** en FIRMS y actualiza los pedidos
de `backend/app/downloads.py`, o repón los archivos del pedido original localmente.
Consulta [la documentación del backend](backend/README.md#español) para usar otras rutas
de datos y preparar las cachés de consulta.

### Borrar datos locales

Con los servidores detenidos, desde la raíz del proyecto:

```bash
npm run data:clean -- --dry-run  # Ver qué archivos se borrarían
npm run data:clean             # Borrar los archivos
```

El script independiente `scripts/clean-data.mjs` elimina los archivos **CSV y ZIP**
de `backend/app/data/` y sus subcarpetas, incluidos resultados CSV de análisis.
Conserva el código Python, los `Readme.txt` y las carpetas, y no sigue enlaces
simbólicos ni junctions. También se puede ejecutar con
`node scripts/clean-data.mjs`. Siempre actúa sobre `backend/app/data/` del proyecto;
no utiliza las rutas externas configuradas con variables de entorno.

Al volver a ejecutar `npm run dev`, se descargarán nuevamente los cuatro conjuntos
FIRMS. Si los enlaces ya vencieron, será necesario actualizar los pedidos primero.
